# index-project

为项目初始化并持续维护跨 code agent 的 AI 上下文索引。使用同一输出契约，按现状选择一条路径：

- **初次索引**：无可靠索引、上次未扫完或用户要求重建时，全量清点并创建文档。
- **跟进索引**：索引完整时检测变化，只读取并更新受影响模块。

以 `AGENTS.md` 为唯一事实来源；`CLAUDE.md` 只保留一行 `@AGENTS.md`，供 Claude Code 确定性导入同目录事实源。Codex 和 OpenCode 直接读取 `AGENTS.md`。不要依赖特定 agent 的专属工具、子代理、MCP 或状态目录；使用宿主提供的等价文件列举、搜索、读取和编辑能力完成流程。

## 确定目标与加载流程

先确定项目根：用户明确指定的目录优先，否则使用当前工作目录。不要仅因当前目录位于某个祖先 Git 仓库中就擅自扩大目标范围。

| 判断条件 | 场景 | 必须加载 |
|---|---|---|
| 无根 `AGENTS.md` | 初次 | `references/first-index.md` |
| 根「索引状态」标记“上次未扫完”，或用户要求全量重建 | 初次（续扫/重建） | `references/first-index.md` |
| 根缺「索引状态」，或模块索引中的模块缺 `AGENTS.md` | 初次（修复） | `references/first-index.md` |
| 根和模块文档完整，仅局部代码或模块变化 | 跟进 | `references/incremental-index.md` |

加载对应 reference 后再扫描或写文档。跟进检测判定基线不可靠或变化范围超过半数非忽略源码文件时，再加载 `references/first-index.md` 并退避为初次索引。

## 公共约束

- 只创建或更新目标范围内根与模块的 `AGENTS.md`、`CLAUDE.md`；不创建 `.claude/`、`.agents/`、`.opencode/` 或机器状态 sidecar。
- Git 项目优先用 Git 的已跟踪、未跟踪和忽略信息列举文件；非 Git 项目使用宿主可用的文件列举能力。始终遵守根和嵌套忽略规则，并默认跳过依赖、构建产物、缓存、日志、媒体、压缩包和二进制文件。
- 不把本 skill 生成的 `AGENTS.md`、`CLAUDE.md` 当作源码新增项或模块文件清单内容。
- 大文件和二进制只记录路径，不读取内容。路径全部写为相对项目根的路径。
- 先读后写并保留人工内容。根或模块存在长 `CLAUDE.md` 时，先将仍有效的正文去重迁入同目录 `AGENTS.md`，确认迁移完成后再收敛 `CLAUDE.md`；不得直接覆盖。人工内容与代码事实冲突时，保留人工内容并向用户说明或确认。
- 不擅自删除文件。模块被移除时先更新索引并报告残留文档；只有用户明确确认后才删除孤儿 `AGENTS.md` 或 `CLAUDE.md`。

若项目没有自己的忽略规则，至少跳过：`node_modules/**`、`.git/**`、`.github/**`、`dist/**`、`build/**`、`.next/**`、`__pycache__/**`、锁文件、日志、媒体、压缩包和常见二进制。

## 记录基线

进入任一流程前获取当前 UTC 时间，格式为 `YYYY-MM-DDTHH:mm:ssZ`；有可验证的项目级 Git 仓库时同时记录当前完整 HEAD，并在文档中显示可辨识的短 commit。不要手写时间。开始时取时间可确保扫描期间发生的新变化在下次运行仍晚于基线。

## 输出契约

- **根 `AGENTS.md`**：项目愿景、架构总览、Mermaid 结构图、模块索引、运行与开发、测试策略、编码规范、AI 使用指引、精简变更记录、文档最末的「索引状态」。图中模块节点链接到对应 `AGENTS.md`。
- **根 `CLAUDE.md`**：仅一行：`@AGENTS.md`
- **模块 `AGENTS.md`**：相对路径面包屑、模块职责、入口与启动、对外接口、关键依赖与配置、适用时的数据模型、测试与质量、常见问题、相关文件清单、精简变更记录。增量流程按标题定位，必须使用精确标题 `## 相关文件清单`；清单只列理解和维护模块所需的高信号文件，不得退化为大型仓库的完整文件 manifest。
- **模块 `CLAUDE.md`**：仅一行：`@AGENTS.md`
- 不适用或未发现的内容明确写“未发现”或省略可选小节，不编造入口、命令、接口或依赖。

根文档最末使用以下状态格式：

```markdown
## 索引状态
- 上次索引：<UTC ISO 时间戳>（Git 项目附 `@<短 commit>`）
- 基线提交：<完整 commit；非 Git 项目写“无”>
- 已知缺口：<无，或未补齐内容>
- 扫描进度：<仅未扫完时记录已完成、待处理和跳过原因；完成后写“已完成”>
```

变更记录只写影响 AI 上下文契约的事实，不复制 Git 历史或无限累积无意义条目。

## 结果摘要

在主对话说明：

- 初次或跟进，以及选择依据；
- 根和模块文档的新建、更新、跳过状态；
- 模块路径与一句话职责；
- 已列举文件数、实际读取内容的文件数、主要缺口和跳过原因；
- 跟进场景的变更清单、更新/跳过说明；无变化时明确说明未写文件；
- 未完成时说明停止原因、已落盘断点和推荐的下一步。
