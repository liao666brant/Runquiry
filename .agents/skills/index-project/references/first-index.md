# 初次索引

从零创建、修复或继续未完成的 AI 上下文索引。公共约束、基线和输出契约见 `../SKILL.md`。

## 1. 建立可恢复断点

先读取目标范围内已有的 `AGENTS.md` 与 `CLAUDE.md`，保存需要保留或迁移的人工内容。再在根 `AGENTS.md` 最末写入：

```markdown
## 索引状态
- 上次索引：上次未扫完
- 基线提交：<本次开始时的完整 HEAD；非 Git 项目写“无”>
- 已知缺口：待扫描
- 扫描进度：待处理“根级清点”
```

若已有未完成状态，先核对已完成模块的 `AGENTS.md` 是否真的落盘且内容完整；只有文档已落盘的模块才算完成。

## 2. 轻量清点

分批列出非忽略文件，不读取依赖目录或生成物。Git 项目优先使用 Git 文件清单；非 Git 项目使用当前宿主可用且遵守嵌套忽略规则的文件列举能力。完成以下清点：

- 文件数量、主要语言和目录拓扑；
- 根 manifest、workspace 配置、README 与开发/测试配置；
- 模块候选：语言 manifest、`apps/*`、`packages/*`、`services/*`、`cmd/*` 及仓库实际采用的其他边界；
- 每个候选模块的语言、可能入口、测试和配置。

候选目录不等于模块：以独立职责、入口/manifest、构建或发布边界为证据确认，避免给每个普通源码目录都生成文档。

清点完成后立即把根「扫描进度」更新为：已完成“根级清点”；待处理“<模块列表>”。

## 3. 按模块扫描并立即落盘

逐模块定点读取高信号文件：

1. 入口和启动脚本；
2. 路由、控制器、公开导出、协议或 API 定义；
3. 依赖、workspace、构建与质量配置；
4. schema、模型和迁移；
5. 测试入口与代表性测试；
6. 仍有效的模块级 `AGENTS.md` 或长 `CLAUDE.md` 人工说明。

每完成一个模块，按以下顺序执行：

1. 写入或段落级更新该模块 `AGENTS.md`；
2. 将该模块长 `CLAUDE.md` 的有效内容迁移完成后，才收敛为一行 `@AGENTS.md`；
3. 复读两份文档确认输出契约和人工内容均保留；
4. 最后更新根「扫描进度」，把该模块从待处理移到已完成。

不要先推进断点再写模块文档，否则中断后会错误跳过尚未持久化的扫描结果。

## 4. 按需补捞

仅在以下情况扩大读取范围：仓库较小；关键职责、接口、数据或测试仍无法判断；现有人工文档提出了尚未核实的事实。只读取解决缺口所需的文件，不粘贴大段源码。

若工具、时间或上下文不足，立即保留“上次未扫完”，准确写出已完成模块、待处理模块、已知缺口和跳过原因。已完成模块文档已经落盘，下一次从待处理列表继续。

## 5. 完成根文档

全部模块完成后：

1. 将根长 `CLAUDE.md` 和旧 `AGENTS.md` 的有效人工内容去重合并到根 `AGENTS.md`；
2. 根据真实模块生成架构、Mermaid 链接和模块索引；
3. 写运行、测试、规范、AI 指引和本次精简变更记录；
4. 用本次开始时取得的时间与 commit 替换未完成占位，将扫描进度写为“已完成”；
5. 复读根 `AGENTS.md`，确认「索引状态」位于文档最末；
6. 最后把根 `CLAUDE.md` 收敛为一行 `@AGENTS.md`。

## 6. 报告覆盖

分别报告“已列举”和“已实际读取内容”的文件数，避免把只看到路径误报为已扫描内容。列出已完成模块、未读目录、二进制/大文件和主要缺口；覆盖率只写进主对话，不把统计噪声写入文档。
