# 跟进索引

Agent 修改模块内容影响现有索引，或用户要求跟进项目变化时使用。同步受影响的模块文档和项目索引是当前开发任务的一部分。公共约束、基线和输出契约见 [SKILL.md](../SKILL.md)。

## 1. 读取基线

从当前任务已知的变更文件和行为出发，读取根 `AGENTS.md` 的模块索引、已有状态及相关模块的高信号「相关文件清单」。定位模块职责、入口、接口、依赖、关键文件和模块关系的变化，不能只检查链接是否可达。用户明确仅维护根文档时，在根索引中同步模块信息。

按公共输出契约整理本次涉及文档的旧记录和重复状态字段。状态中的产品待办或验收记录不作为索引缺口；纯整理不建立新起点、不推进基线。

有未完成扫描或实际文档缺口时，核对已有产物并补齐受影响部分；只有无法据现有证据定向完成时，才加载 [初次索引](first-index.md) 补充扫描。缺少状态格式本身不要求重建。

先确定 Git 模式：只有 `git -C <项目根> rev-parse --show-toplevel` 的规范化结果等于项目根，才把它视为项目级 Git 仓库；祖先仓库不算。

## 2. 检测变化

本次开发变更已知时，以该范围及受影响的索引引用做定向核对。需要跟进上次索引以来的全部变化，或当前任务信息不足时，再使用下面的 Git、结构或时间证据补充候选。

### Git 项目

优先从「基线提交」读取完整 commit；旧索引没有该字段时，可提取「上次索引」里的旧式 `@<短 commit>`。仅在该值能唯一解析为 commit 时使用，并在完成约定范围的核对后补写完整基线。基线有效时合并以下名称级变化：

- 已提交：`git diff --name-status <基线提交>..HEAD`
- 已暂存：`git diff --cached --name-status`
- 未暂存：`git diff --name-status`
- 未跟踪：`git ls-files --others --exclude-standard`

不要用 `git diff HEAD` 代替基线 diff；它会漏掉上次索引后已经提交、但当前工作树干净的变化。将重命名、复制、删除和类型变化按 Git 状态正确归类。`AGENTS.md`、`CLAUDE.md` 的差异需读取实际内容后判断，不能仅凭路径认定为新的人工编辑或待更新内容。

基线 commit 缺失或已不可解析时，先使用下述非 Git 结构与时间检测补救；仍不能可靠界定变化范围就退避为初次索引，不猜测。

### 结构检测

- 将根模块索引与实际 manifest/workspace/模块目录对比，识别新增、移除和缺文档模块。
- 检查已记录的高信号文件是否被新增、删除或重命名；不要把生成的 `AGENTS.md`、`CLAUDE.md` 当作源码变化。
- 根 manifest 或 workspace 配置变化时重新确认模块边界；只有边界发生广泛变化才退避全量，不因普通脚本字段变化直接全扫。

### 非 Git 内容检测

以根「上次索引」时间为统一基线，比较非忽略源码文件和目录的 mtime。使用宿主支持的元数据能力；若调用 shell，兼容 GNU/BSD `stat` 差异，不硬编码单一平台参数。目录 mtime 变化用于发现未列入高信号清单的新增/删除，再定向列举该目录确认。

mtime 被保留或回拨时可能漏检，例如归档恢复、`rsync -a`、快照或手工回写时间。发现此类迹象或用户明确指出未被检测的变化时，退避初次索引并在摘要说明原因。

### 退避与无变化

只有模块边界或基线的缺口使必要覆盖范围无法确定时，才加载 `first-index.md` 补充扫描并说明原因，不按变更文件占比强制全量。

Git diff 和 mtime 只提供候选。核对现有模块内容摘要、文件清单和索引引用；来源变化可能已经被文档吸收。现有索引准确、符合当前输出契约且没有新缺口或进度时，立即结束并说明“无实质变化”，保留文档、时间戳及基线。

## 3. 定向更新

| 变化 | 动作 |
|---|---|
| 新增模块 | 扫描该模块，按现有索引层级创建模块 `AGENTS.md` 和一行 `@AGENTS.md` 的 `CLAUDE.md`，更新根索引与 Mermaid；仅维护根文档时在根索引中记录模块 |
| 模块职责、入口、接口、依赖、模型或测试变化 | 只读相关变化文件及必要上下文，更新对应小节和高信号文件清单，并同步根与其他模块中受影响的索引条目 |
| 文件或模块重命名、移除 | 更新职责、接口、清单和根引用；报告残留文档，未经明确确认不删除文件 |
| 根 manifest/workspace 变化 | 重新确认模块边界，更新架构、运行命令和模块索引 |
| 人工编辑 `AGENTS.md` 或长 `CLAUDE.md` | 保留并调和人工内容；长 `CLAUDE.md` 先迁移再收敛 |

人工修改与代码事实变化按公共约束调和，不因出现在同一段就视为冲突。使用标题为锚点做最小补丁，不整篇重写。

## 4. 完成更新

1. 按约定层级复读并验证受影响的索引内容：模块级模式检查对应模块文档，仅根级模式检查根文档中的对应模块信息；未变化模块不读取源码、不重写其索引内容。
2. 同步根架构、Mermaid、模块索引及其他模块中受影响的当前引用；相关模块内容和项目索引均准确才算完成，无关小节保持原样。
3. 本轮完成约定索引范围的核对且内容或真实进度有变化时，才将原始扫描起点提升为全局基线。局部模块更新或旧记录整理保留原全局基线；仍有待处理模块时保留原始起点与当前断点，不能因局部任务完成而标为全局已完成。
4. 确认根「索引状态」只有一份且位于文档最末、各字段唯一；完成的扫描只保留“已完成”，没有新增工作日志或每轮进度历史。所有需收敛的 `CLAUDE.md` 已先完成内容迁移。
5. 输出新增、修改、删除、跳过和未获授权删除的清单，并说明 Git 或 mtime 检测的证据与盲区。
