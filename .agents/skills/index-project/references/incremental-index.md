# 跟进索引

在完整索引上只检测并更新变化的部分。公共约束、基线和输出契约见 `../SKILL.md`。

## 1. 读取基线

读取根 `AGENTS.md` 的模块索引与「索引状态」，再读取模块文档中的高信号「相关文件清单」。若状态缺失、标记“上次未扫完”、基线无法解释，或索引中的模块缺 `AGENTS.md`，加载 `first-index.md` 并改走初次索引。

先确定 Git 模式：只有 `git -C <项目根> rev-parse --show-toplevel` 的规范化结果等于项目根，才把它视为项目级 Git 仓库；祖先仓库不算。

## 2. 检测变化

### Git 项目

优先从「基线提交」读取完整 commit；旧索引没有该字段时，可提取「上次索引」里的旧式 `@<短 commit>`。仅在该值能唯一解析为 commit 时使用，并在本次更新后补写完整基线。基线有效时合并以下名称级变化：

- 已提交：`git diff --name-status <基线提交>..HEAD`
- 已暂存：`git diff --cached --name-status`
- 未暂存：`git diff --name-status`
- 未跟踪：`git ls-files --others --exclude-standard`

不要用 `git diff HEAD` 代替基线 diff；它会漏掉上次索引后已经提交、但当前工作树干净的变化。将重命名、复制、删除和类型变化按 Git 状态正确归类。`AGENTS.md`、`CLAUDE.md` 的变化用于识别人工文档编辑，但不计入源码变化比例。

基线 commit 缺失或已不可解析时，先使用下述非 Git 结构与时间检测补救；仍不能可靠界定变化范围就退避为初次索引，不猜测。

### 所有项目都做的结构检测

- 将根模块索引与实际 manifest/workspace/模块目录对比，识别新增、移除和缺文档模块。
- 检查已记录的高信号文件是否被新增、删除或重命名；不要把生成的 `AGENTS.md`、`CLAUDE.md` 当作源码变化。
- 根 manifest 或 workspace 配置变化时重新确认模块边界；只有边界发生广泛变化才退避全量，不因普通脚本字段变化直接全扫。

### 非 Git 内容检测

以根「上次索引」时间为统一基线，比较非忽略源码文件和目录的 mtime。使用宿主支持的元数据能力；若调用 shell，兼容 GNU/BSD `stat` 差异，不硬编码单一平台参数。目录 mtime 变化用于发现未列入高信号清单的新增/删除，再定向列举该目录确认。

mtime 被保留或回拨时可能漏检，例如归档恢复、`rsync -a`、快照或手工回写时间。发现此类迹象或用户明确指出未被检测的变化时，退避初次索引并在摘要说明原因。

### 退避与无变化

变化的非忽略源码文件超过全仓一半、模块边界广泛改变，或基线不可靠时，加载 `first-index.md` 改走初次索引并说明原因。

若代码、模块边界和人工文档都没有变化，立即结束：不要重写任何文档，不刷新时间戳或变更记录，只在摘要说明“无变化”。

## 3. 定向更新

| 变化 | 动作 |
|---|---|
| 新增模块 | 扫描该模块，创建模块 `AGENTS.md` 和一行 `@AGENTS.md` 的 `CLAUDE.md`，更新根索引与 Mermaid |
| 模块内入口、接口、依赖、模型或测试变化 | 只读相关变化文件及必要上下文，段落级更新对应小节和高信号文件清单 |
| 文件或模块移除 | 更新职责、接口、清单和根引用；报告残留文档，未经明确确认不删除文件 |
| 根 manifest/workspace 变化 | 重新确认模块边界，更新架构、运行命令和模块索引 |
| 人工编辑 `AGENTS.md` 或长 `CLAUDE.md` | 保留并调和人工内容；长 `CLAUDE.md` 先迁移再收敛 |

同一段同时包含人工修改和代码事实变化时，不覆盖人工内容；指出冲突并向用户确认。其他段落使用标题为锚点做最小补丁，不整篇重写。

## 4. 完成更新

1. 只复读并验证受影响模块文档；未变化模块不读取源码、不重写文档、不改变 mtime。
2. 更新根架构、Mermaid、模块索引和精简变更记录。
3. 将根「上次索引」和「基线提交」更新为本次开始时取得的值，刷新真实缺口并写“扫描进度：已完成”。
4. 确认根「索引状态」仍在文档最末，所有需收敛的 `CLAUDE.md` 已先完成内容迁移。
5. 输出新增、修改、删除、跳过和未获授权删除的清单，并说明 Git 或 mtime 检测的证据与盲区。
