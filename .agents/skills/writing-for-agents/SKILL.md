# Agent 文档写作

本参考适用于 Agent 会读取的任何文档：Skill、`AGENTS.md`、`CLAUDE.md`，以及由指针引用的说明。它们的包装形式不同，写作原则相同：目标是让 Agent 每次遵循同一套**过程**，而不是机械地产出相同结果。

编写 Skill 时，读取 [Skill 机制](references/skill-mechanics.md)，了解 frontmatter、调用方式和路由 Skill。

## 上下文指针

**上下文指针**是 Agent 上下文中的一段引用：它命名某个尚未载入的材料，并编码何时应读取该材料。Skill 的 `description` 是指针，`AGENTS.md` 中指向其他文档的一行也是指针。决定 Agent 是否可靠抵达目标的是指针的措辞，而不是目标本身。必要材料如果藏在措辞薄弱的指针后面，就会产生行为偏差；先强化指针，仍不可靠时才把材料内联。

指针承担两个职责：说明材料是什么，并列出应触发读取的**分支**。分支是文档处理的独立情形，不同运行会沿不同分支推进。指针始终占用上下文，因此每个词都应比正文经受更严格的删减：

- **把引导词放在最前。** 指针的首要作用是触发。
- **每个分支只写一个触发条件。** 仅仅换一种说法的同义词仍是同一分支，应合并；只保留真正不同的分支。
- **删除正文已经表达的身份信息。**

## 两种负载

每份文档和每个指针都会消耗两种预算之一：

- **上下文负载**：始终加载到 Agent 窗口中的材料所产生的成本，例如 `AGENTS.md` 的一行、Skill 描述，以及每轮无论是否触发都会占用 token 和注意力的内容。
- **认知负载**：人需要记住有哪些文档、何时读取它们的成本。人就是索引。认知负载不是越低越好，而是保留人类判断所需的代价；在人类判断重要的地方使用它，在不重要的地方消除它。

只通过指针抵达的材料免于正文的上下文负载，但仍要支付指针本身的成本；完全没有指针的材料则全部依赖人的认知负载。

## 信息层级

文档由两类内容组成：**步骤**是 Agent 按顺序执行的动作，**参考**是按需查询的定义、规则和事实。二者可以自由组合。核心决定是每部分内容位于哪个**信息层级**，按即时需求从高到低排列：

1. **文件内步骤**是主层级：Agent 按顺序执行的动作。
2. **文件内参考**按需查阅。多个规则处于同一层级并不天然是问题。
3. **渐进披露的参考**放到独立文件，通过上下文指针按条件加载；既可以是同目录文件，也可以是外部资料。

下沉太少会让顶层膨胀，下沉太多又会隐藏 Agent 实际需要的材料，二者之间的张力就是层级设计的核心。

**渐进披露**是把内容沿层级下移到指针之后，使顶层保持清晰。它首先是保护信息层级的方法，不只是 token 优化。最可靠的判断标准是分支：所有分支都需要的内容内联，只有部分分支需要的内容放到指针后。对含步骤的文档而言，本应披露的参考会掩埋步骤，使 Agent 是否注意到步骤变得不稳定。

**共置**解决同一文件内的组织问题：层级决定内容放多深，共置决定内容到达该层后与什么放在一起。把一个概念的定义、规则和例外集中在同一标题下，让阅读其中一部分时同时看到相邻约束。重复是在多处表达同一含义；散落则是把一个含义拆散到多处，二者都应避免。

**蔓延**是文档过长的失效模式，即使每一行都独特且有效，过量内容仍会稀释注意力并增加维护面。沿信息层级披露参考，并按分支或顺序拆分，让每条路径只携带自己需要的内容。

## 步骤与完成条件

每个步骤都应以**完成条件**结束，让 Agent 能判断该步骤是否真正完成。完成条件有两个属性：

- **清晰度**：Agent 能否区分完成与未完成？“已经理解”之类模糊边界会诱发**提前完成**。后续可见步骤会拉扯 Agent 尽快结束当前步骤。先收紧边界；只有边界本身不可避免地模糊，且真实运行中确实出现抢跑时，才通过拆分顺序隐藏后续步骤。隐藏必须跨越真实上下文边界，例如交接或子 Agent 调度；同一上下文内的内联调用不会消除这种拉扯。
- **要求强度**：条件要求 Agent 做到什么程度。“覆盖每个已修改模型”会带来比“生成变更列表”更彻底的查证。要求强度驱动**实地工作**，不只属于步骤；“应用每条规则”同样能约束一组平铺参考。

最强的完成条件既可检查，又要求覆盖完整。

## 何时拆分

把一份文档拆成两份会增加上下文指针或认知负载，因此只在拆分能回收这笔成本时使用：

- **按顺序拆分**：当后续步骤会诱使 Agent 草率结束当前步骤时，把后续步骤移出当前上下文。反过来，合并两个序列会让前一个序列看到更多后续步骤，可能增加提前完成。
- **按调用方式拆分**：仅适用于 Skill，参见 [Skill 机制](references/skill-mechanics.md)。

## 引导词

**引导词**是模型预训练中已有、能在执行文档时直接调用的紧凑概念，例如“教训”“战争迷雾”“曳光弹”。重复的是这个词，而不是解释句；它以最少 token 锚定一整片行为，并利用模型已有先验。

自造词也能工作，但无法利用既有先验，需要用定义补回成本，因此优先选择已经存在的概念。引导词有两种作用：在正文中锚定执行行为；在指针中，当提示、文档和代码库使用同一术语时，提升 Agent 抵达目标材料的可靠性。

主动寻找可用引导词收敛的重复表达：

- “快速、确定、低开销”可以收敛为“紧凑”。
- “一个你确信有效的循环”可以收敛为“红灯”，把模糊门禁变成二元状态：循环能否让缺陷变红。

这样既减少 token，也给 Agent 提供更清晰的思考锚点。

**否定式指令**会把被禁止的行为带入上下文，使它反而更容易被想到。优先描述正向目标，例如直接要求“写单行注释”。只有无法正向表达的硬性护栏才使用禁止语句，并同时给出目标行为，让注意力落在应该做什么上。

## 删减

- 每个含义只保留一个**事实来源**。重复会增加维护和 token 成本，还会人为放大该含义的重要程度；引导词重复的是词，不是含义。
- 环境本身也是事实来源，例如 `package.json` 脚本、配置、目录结构和 `--help` 输出。文档复述这些信息等于维护缓存；只缓存难以从环境发现的内容，如未成文约定、决策原因和配置无法表达的陷阱。容易查到的一文件、一命令信息留在环境中。
- 逐行检查**相关性**：该行是否仍影响当前文档的任务？纯背景说明、应被披露的分支和已经过期的事实都应移除。较短的文档更容易保持相关。
- 逐句寻找**无效指令**：如果 Agent 默认就会这样做，该句只是在为零行为变化支付上下文成本。用真实运行判断默认行为；一条指令无效时删除整句，不要只修剪措辞。引导词也接受同一检查：无法改变默认行为的弱词应换成更强的词，而不是继续堆叠解释。
