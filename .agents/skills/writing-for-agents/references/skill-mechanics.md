# Skill 机制

这是 [Agent 文档写作](../SKILL.md) 中仅适用于 Skill 的分支：说明 frontmatter、调用方式和路由 Skill。其余写作原则以主 `SKILL.md` 为准。

## 调用方式

调用策略在两种负载之间取舍：

- **允许 Agent 自动调用**：保留可触发的 `description`，让 Agent 能根据任务自主选择该 Skill，其他工作流也能引用它。用户仍可显式输入 Skill 名称。`description` 是顶层上下文指针，应携带真正不同的触发分支，并遵循主文档的指针写法。纯参考型 Skill 也可以作为多项工作共享的单一事实来源，但只有当 Agent 确实需要自主抵达它时，持续发现成本才值得。
- **仅允许用户显式调用**：只有人输入 Skill 名称时才执行，以较高认知负载换取更低的自动发现成本。具体机制因宿主不同：支持相应 frontmatter 的宿主可使用 `disable-model-invocation: true`；Codex 在 `agents/openai.yaml` 中使用 `policy.allow_implicit_invocation: false`。不同宿主是否仍暴露名称、描述或路径并不一致，因此不要把显式调用模式描述为跨宿主“零上下文成本”。此时 `description` 应改为面向人的一句话摘要，去掉自动匹配所需的触发词列表。

只有 Agent 必须自行发现该 Skill，或其他工作流必须引用它时，才启用自动调用。纯手动工作流应使用宿主支持的显式调用策略。

多个显式调用 Skill 共享的参考不应复制到每个 Skill 中。把它放到 Skill 系统之外的普通文件，由各 Skill 直接指向同一事实来源。

## 按调用方式拆分

当某个分支拥有独立且稳定的引导词，确实应该自行触发，或必须由其他工作流抵达时，才把它拆成可自动调用的 Skill。新的常驻描述会增加发现成本，只有独立触发能力能偿还这项成本时才拆分。

## 路由 Skill

当显式调用 Skill 多到难以记忆时，可以用一个路由 Skill 降低认知负载：它列出其他 Skill 及适用条件，让人只需记住一个入口。路由能力取决于宿主；如果显式调用策略阻止 Agent 或其他 Skill 调用目标，路由 Skill 只能提示用户，不能代替用户触发目标 Skill。
