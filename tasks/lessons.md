# 提交范围

- 提交前区分源码、直接测试、正式文档与本地过程产物。运行日志、临时截图、缓存和 Agent 执行状态默认仅保留本地；同属一个开发任务不等于应一起提交。
- 按明确文件清单暂存，核对新增文件与忽略规则；只有用户明确要求时才将运行证据纳入版本控制。

# WSL 构建红线（本仓库特有教训，2026-09-07）

- 本机 WSL（15 GiB）在 `cargo test` 的链接阶段会因内存峰值整机卡死（Batch 6 两次复现：多子代理并发 cargo、单个全量 test 二进制批量链接都触发过）。验证策略：编译用 `cargo check`（不链接）；跑测试一次只构建/运行一个定向测试二进制并 `-j 1`；绝不并行跑两路 cargo；除非用户明确要求，不做全量 workspace 测试。
- 派发子代理时必须明令禁止运行 cargo（子代理默认会跑测试验证），并在提示词写明原因，否则会绕过主会话的构建约束。

# 测试代码 lint 基线（本仓库特有教训，2026-09-07）

- 根 `Cargo.toml` 将 `unwrap_used`/`expect_used` 设为 deny 且仓库没有 `clippy.toml`（未启用 `allow-unwrap-in-tests`），因此 **`#[cfg(test)]` 内联测试与 tests/ 目录同样不得使用 `.unwrap()`/`.expect()`/`panic!`**。新测试统一用 `Result + ?` / `.unwrap_or(...)` / `assert!(x.is_ok_and(...))`；给生产错误类型补 `Display + Error` impl 属独立决策，不为测试便利顺手加。
